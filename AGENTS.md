\\# Agent Skills — OpenCode







\\## Core Instructions







Before starting a coding task, identify the most relevant installed skill and load it using OpenCode's built-in skill tool.







Follow the selected skill's workflow, including its verification requirements. Do not claim a skill was used unless it was actually loaded.







\\## Task-to-Skill Mapping







\\- Unclear requirements: `interview-me`



\\- Refine an idea: `idea-refine`



\\- New feature or significant change: `spec-driven-development`



\\- Define project quality standards: `constraint-driven-development`



\\- Break down implementation tasks: `planning-and-task-breakdown`



\\- Implement changes incrementally: `incremental-implementation`



\\- Write or modify logic: `test-driven-development`



\\- Fix bugs: `debugging-and-error-recovery`



\\- API and interface design: `api-and-interface-design`



\\- Frontend and UI development: `frontend-ui-engineering`



\\- Code review: `code-review-and-quality`



\\- Simplify existing code: `code-simplification`



\\- Security and authentication: `security-and-hardening`



\\- Performance issues: `performance-optimization`



\\- Framework documentation verification: `source-driven-development`



\\- Database migrations and deprecations: `deprecation-and-migration`



\\- CI/CD and deployment automation: `ci-cd-and-automation`



\\- Production launch: `shipping-and-launch`



\\- Production observability: `observability-and-instrumentation`



\\- Git operations: `git-workflow-and-versioning`



\\- Documentation and architecture decisions: `documentation-and-adrs`



\\- Browser testing: `browser-testing-with-devtools`



\\- High-risk or unfamiliar changes: `doubt-driven-development`



\\- Production readiness: `shipping-and-launch`



\\- Choosing the appropriate workflow: `using-agent-skills`







\\## Execution Rules







1\\. Inspect the existing architecture and relevant files before making changes.



2\\. State important assumptions and clarify ambiguities before implementing significant changes.



3\\. Reuse existing components and dependencies where appropriate.



4\\. Avoid unrelated refactoring and unnecessary abstractions.



5\\. Follow applicable testing, security, and validation requirements.



6\\. Run the relevant verification commands and report their actual results.



7\\. Explain remaining risks and unverified behavior.



8\\. Do not modify files outside the requested scope without permission.
